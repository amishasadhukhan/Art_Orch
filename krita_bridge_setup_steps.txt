ART ORCH — KRITA BRIDGE SETUP STEPS
=====================================
Run this whole sequence every time you want Colab to send generated
code directly into a running Krita instance on this machine.

(ngrok sign-in/authtoken is ONE-TIME-EVER, already done on this machine —
not needed again below.)


ONE-TIME SETUP (only needed once per machine, or after reinstalling Krita)
----------------------------------------------
1. Install the Art Orch Bridge Krita plugin:
   - In Krita: Settings > Manage Resources > Open Resource Folder
     This opens a folder like %APPDATA%\krita\
   - Inside it, open (or create) the "pykrita" subfolder.
   - Copy BOTH of these from this repo's krita_bridge_plugin/pykrita/ into
     that pykrita folder:
       art_orch_bridge.desktop
       art_orch_bridge/            (the whole subfolder, with its .py files)
   - Restart Krita.

2. Enable the plugin:
   - Settings > Configure Krita > Python Plugin Manager
   - Check the box next to "Art Orch Bridge"
   - Click OK, then restart Krita again.

3. Make sure brush presets are enabled (only if you ever see
   "no brush presets available" — otherwise skip this):
   - Settings > Manage Resources > Manage Resource Libraries
   - For each bundle listed (Krita_3_Default_Resources,
     Krita_4_Default_Resources, RGBA_brushes,
     Krita_Artists_SeExpr_examples): select it, and if the button says
     "Activate" (not "Deactivate"), click Activate.
   - Click Close, then restart Krita.
   - If presets are STILL missing after that: close Krita, go to
     Settings > Manage Resources > Open Resource Folder, delete the file
     resourcecache.sqlite, then restart Krita to force it to rebuild.


EVERY SESSION — do these three, in this order
----------------------------------------------

STEP 1 — Open Krita (this also starts the bridge's HTTP server on port
8765, since the plugin auto-starts it when Krita launches):

    & "C:\Program Files\Krita (x64)\bin\krita.exe"


STEP 2 — Verify the bridge is listening
(should print "2" — the result of 1+1 executed inside Krita):

    Invoke-WebRequest -Uri http://127.0.0.1:8765 -Method POST -Body "print(1+1)" -UseBasicParsing

    If this fails/times out, the plugin didn't start — check
    %USERPROFILE%\art_orch_bridge_error.log for the error, and confirm
    the plugin is enabled in Settings > Configure Krita > Python Plugin
    Manager.


STEP 3 — Start the ngrok tunnel so
Colab (a remote machine) can reach your local port 8765:

    ngrok http --domain=tipoff-thieving-greasily.ngrok-free.dev 8765

    Your bridge URL for Colab is:
        https://tipoff-thieving-greasily.ngrok-free.dev


THEN IN COLAB
----------------------------------------------
Set BRIDGE_URL to the ngrok domain above and run your pipeline

In colab cell after uploading the outline_generator.py and the json file:

BRIDGE_URL = "https://tipoff-thieving-greasily.ngrok-free.dev"  # your running ngrok tunnel URL

import outline_generator
outline_generator.run("boy_sitting1.json", bridge_url=BRIDGE_URL)

import outline_generator as og
og.fetch_canvas_image(BRIDGE_URL, "generated.png")
og.compare_images("generated.png", "/content/Screenshot 2026-07-22 214327.png")


FULL REFERENCE-IMAGE-TO-PLAN PIPELINE (image_to_plan.py) — LOCAL TERMINAL
----------------------------------------------
This is the full loop: reference image -> plan JSON -> render in Krita ->
export the result -> critique it against the reference -> auto-correct the
JSON -> repeat. Run these from a local PowerShell terminal in the repo
folder (not Colab) — image_to_plan.py calls the HF model directly.

STEP 0 — Set your Hugging Face API key for this terminal session
(get one from https://huggingface.co/settings/tokens if you don't have it;
rotate/regenerate it if it's ever been pasted anywhere insecure):

    $env:HF_TOKEN = "hf_your_actual_token_here"

    This only lasts for this terminal window/session — you'll need to set
    it again next time you open a new terminal. To make it permanent
    instead:
        [Environment]::SetEnvironmentVariable("HF_TOKEN", "hf_your_actual_token_here", "User")
    (then close and reopen the terminal for it to take effect).


STEP 1 — Generate the initial plan JSON from a reference image
(use any file under Dataset/ as the schema example — it just needs to be
a valid plan JSON, it doesn't have to resemble your new reference image):

    python image_to_plan.py generate <reference_image.png> Dataset/boy_outline1.json --out plan.json

    If this fails with a JSON parse error, check last_raw_model_output.txt
    (auto-saved on failure) — usually means the model's response got cut
    off; raise max_tokens in image_to_plan.py if so.


STEP 2 — Make sure Krita + the bridge + ngrok are running (see the
EVERY SESSION steps above), then render the plan into Krita:

    python -c "import outline_generator as og; og.run('plan.json', bridge_url='https://tipoff-thieving-greasily.ngrok-free.dev')"

    Note: this adds new layers on top of whatever's already open in Krita
    rather than clearing the canvas — close and reopen the Krita document
    before re-rendering a corrected plan, so old attempts don't visually
    stack underneath the new one.


STEP 3 — Pull the actual rendered canvas back as a PNG, so you (and the
critic model) can see what was actually painted:

    python -c "import outline_generator as og; og.fetch_canvas_image('https://tipoff-thieving-greasily.ngrok-free.dev', 'generated.png')"

    Open generated.png to look at it yourself (e.g. `start generated.png`).


STEP 4 — Run the correction pass. This ALONE both diagnoses the errors
(prints the critic's findings to the terminal) AND fixes the plan JSON
using that diagnosis, in one model-call pair — do not run a separate
"critique" command first, that just wastes an extra API call:

    python image_to_plan.py correct plan.json generated.png <reference_image.png> --out plan.json

    (--out plan.json overwrites the same file so the loop can repeat
    cleanly; use a different name if you want to keep each version.)


STEP 5 — Repeat from STEP 2 (re-render the corrected plan.json, re-export,
re-correct) until the picture matches the reference closely enough.


OPTIONAL — check similarity numerically instead of just eyeballing it:

    python -c "import outline_generator as og; og.compare_images('generated.png', '<reference_image.png>')"

    (requires: pip install scikit-image pillow numpy)
